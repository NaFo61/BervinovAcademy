## Цель работы

Научиться связывать браузер, Python (Flask) и базу данных. Показать каталог из двух связанных таблиц и отфильтровать его параметрами GET-запроса. Запрос к базе собирать так, чтобы данные из адресной строки не могли изменить текст SQL.

---

## Вариант

Вариант 2, банк.

- Основная таблица — банковские продукты.
- Вспомогательная — аудитория («для кого»): работающие, пенсионеры, студенты, компании, самозанятые.
- Связь один-ко-многим: у продукта одна аудитория, у одной аудитории много продуктов.
- Поля продукта: картинка, название, для кого предназначено, описание, стоимость тарифа.
- Номер аудитории хранится в таблице продуктов, название берётся соединением таблиц.

## Почему Flask и SQLite, а не PHP и MySQL

| Было | Стало | Зачем |
|------|-------|-------|
| PHP + Apache (XAMPP) | Python + Flask | Один язык, проще запуск: `python app.py` |
| MySQL / MariaDB | SQLite | Один файл базы, без пароля и отдельной службы |
| `products.php` | маршрут `/products` | Та же страница с формой GET |
| PDO `?` / `:name` | `sqlite3` и `?` | Те же подготовленные выражения |

**Есть ли смысл оставлять MySQL?**  
Для этой лабораторной — нет. Нужны JOIN, фильтр и безопасные параметры: SQLite это умеет. MySQL удобнее, когда к базе ходят много пользователей сразу или база должна жить на отдельном сервере.

## Ход работы

1. По файлу `schema.sql` создаются таблицы `audiences` и `products`. Поле `audience_id` — внешний ключ. Картинка хранится как имя файла в `static/catalog_images`. Стоимость тарифа — целое число рублей.

2. В справочник внесены пять аудиторий. В продукты — шесть записей: Альфа-Карта и Альфа-Карта Premium для работающих, пенсионная, студенческая, карта для бизнеса (590 ₽), карта самозанятого (199 ₽). Premium — 2990 ₽, остальные бесплатные — 0.

3. Файл `logic.py` открывает SQLite и готовит выборку. Базовый запрос соединяет `products` и `audiences` через `INNER JOIN`. Если в GET нет `clearFilter`, к запросу добавляется `WHERE`. Пустое поле в условие не входит. Несколько полей соединяются через `AND`.

   Условия:
   - название и описание — `LIKE` по подстроке;
   - аудитория — целое число;
   - стоимость тарифа — равенство.

   Значения передаются в `execute` списком, не склейкой SQL. Символы `%`, `_` и `\` в тексте пользователя экранируются, у `LIKE` указан `ESCAPE`.

   Особенность SQLite: встроенный `LOWER` не трогает кириллицу, поэтому для поиска без учёта регистра используется функция `py_lower` из Python. Иначе запрос `name=карт` не нашёл бы «Альфа-Карта».

4. Форма в шаблоне `products.html` отправляется методом GET на `/products`. Кнопка «Очистить» добавляет `clearFilter`, и условия не ставятся. После очистки поля формы показываются пустыми.

5. Вывод — таблица Bootstrap. Jinja2 по умолчанию экранирует HTML (`{{ ... }}`), чтобы описание не вставило свой код. Число найденных строк пишется над таблицей. Если строк нет — пояснение.

6. Шапка каталога ссылается на главную `/`. Картинки отдаёт маршрут `/images/<filename>`.

## Проверка фильтра

1. Без параметров `/products` показывает все 6 продуктов. В колонке «Для кого» — названия из `audiences`, не номера.
2. Адрес `?audience_id=4` оставляет одну строку: «Карта для бизнеса», 590 ₽.
3. Адрес `?name=карт&audience_id=1&description=кэшбэк&tariff_cost=0` оставляет «Альфа-Карта». Premium отсекается стоимостью 2990.
4. Адрес `?name=неттакого` показывает пустой список.
5. Кнопка «Очистить» возвращает все 6 строк.
6. Строка с кавычкой и словом `drop` в названии не меняет SQL: значение уходит параметром. Таблицы остаются на месте.

## Выводы

Каталог читается из двух таблиц одним запросом со связью один-ко-многим. Фильтр живёт в адресе, поэтому ссылку можно открыть заново и получить тот же результат. Текст SQL не собирается из кусков браузера: меняется только набор условий, значения идут через подготовленное выражение. На Python + Flask + SQLite цель лабораторной достигается так же, как на PHP + MySQL, но без установки отдельного сервера базы.
