# FEATURE: Промокод на Про + сертификат курса

Status: **IMPLEMENTED**

Одобрено владельцем («сделай»).

## Зачем

1. Владелец создаёт промокод в админке. Ученик вводит его — включается тариф Про.
2. После **100%** курса ученик видит именной сертификат.
3. Блок «Достижения» убираем — он не нужен.

## Как пользуется человек

- **Промокод:** страница «Про» → поле «Промокод» → «Применить». Про на срок из кода (обычно 30 дней). Один человек — один раз на код.
- **Сертификат:** курс на 100% → кнопка «Открыть сертификат» (курс, профиль, страница обучения). Можно распечатать.
- **Админка:** «Промокоды» — создать код, лимит использований, срок. «Сертификаты» — список выданных.

## API

| Метод | Путь | Кто | Что |
|-------|------|-----|-----|
| POST | `/api/subscriptions/redeem/` | JWT | `{ "code": "EGE2026" }` → подписка |
| GET | `/api/progress/certificates/` | JWT | мои сертификаты |
| GET | `/api/progress/certificates/<uuid>/` | все | один сертификат (ссылка) |

`/api/users/me/` — поле `certificates`, без `achievements`.
Запись на курс и прогресс курса — `certificate_public_id`, если курс пройден.

Ошибки промокода (400): нет такого, истёк, отключён, уже использован, лимит исчерпан.

## База

- `PromoCode`, `PromoRedemption` (подписки)
- `CourseCertificate` (прогресс): один на пару ученик+курс, выдаётся при 100%
- Источник выдачи Про: `promo`

Достижения в БД остаются (не ломаем старые миграции), но API и сайт их больше не показывают.

## UI

- `/pro` — форма промокода
- `/certificate?id=…` — красивый документ + печать
- Профиль: сертификаты вместо достижений
- Курс / обучение: кнопка при 100%

## Вне скоупа

Оплата картой, несколько тарифов, публичная витрина чужих сертификатов в каталоге.
