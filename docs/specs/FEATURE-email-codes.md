# FEATURE: Код на почту — сброс пароля и подтверждение email

Status: **IMPLEMENTED** (2026-08-13)

## Зачем

Человек забывает пароль или хочет убедиться, что почта его.  
Сайт шлёт **6-значный код на email**. По коду можно:

1. **Сбросить пароль** (уже есть форма «Забыли пароль?» — доводим до реальной отправки).
2. **Подтвердить почту** в профиле (нового ещё нет).

Сейчас на проде SMTP **не настроен** — письма не доходят. Логика сброса пароля в коде есть, но без почтового ящика она бесполезна.

## Как будет для человека

### Сброс пароля
1. На входе → «Забыли пароль?» → вводит email.
2. На почту приходит код (15 минут).
3. Вводит код + новый пароль → входит с новым паролем.

### Подтверждение почты
1. В профиле, если email есть, но ещё не подтверждён — мягкий баннер «Подтверди почту».
2. Кнопка «Отправить код» → код на почту.
3. Ввод кода → почта помечена как подтверждённая.

**Не блокируем** вход и учёбу, если почта не подтверждена (только мягкое напоминание).

## Acceptance criteria

- [ ] При сбросе пароля по email код реально уходит письмом (не только в логи).
- [ ] Неверный / просроченный код → понятная ошибка; лимит запросов как сейчас (`10/min`).
- [ ] Если аккаунта нет — тот же общий ответ («если аккаунт найден…»), без утечки.
- [ ] У пользователя есть флаг «почта подтверждена».
- [ ] Залогиненный может запросить код подтверждения на **свой** email и подтвердить его.
- [ ] После успешного подтверждения в профиле видно «почта подтверждена».
- [ ] При регистрации с email почта сначала **не** подтверждена; после кода — да.
- [ ] Вход через **Яндекс**, если email пришёл от Яндекса — считаем почту уже подтверждённой.
- [ ] В DEBUG по-прежнему можно вернуть `dev_code` в ответе API (для тестов).
- [ ] Pytest на сброс + подтверждение.
- [ ] В `.env.example` / `.env.prod.example` — переменные SMTP.

## API

### Уже есть (дорабатываем отправку)

| Method | Path | Auth | Body |
|--------|------|------|------|
| POST | `/api/auth/password-reset/request/` | AllowAny | `{ "login": "email или телефон" }` → `{ message, dev_code? }` |
| POST | `/api/auth/password-reset/confirm/` | AllowAny | `{ login, code, password, password_confirm }` |

Телефон: как сейчас — код в лог (SMS вне scope). Email — через SMTP.

### Новое

| Method | Path | Auth | Body / notes |
|--------|------|------|--------------|
| POST | `/api/auth/email-verify/request/` | JWT | Пусто или `{}` → шлёт код на `user.email`. Нет email → 400. Уже verified → 200 «уже подтверждена». |
| POST | `/api/auth/email-verify/confirm/` | JWT | `{ "code": "123456" }` → ставит `email_verified=true` |

В `/api/users/me/` (и recovery/profile): добавить `email_verified: bool`.

## DB

`User.email_verified` — `BooleanField(default=False)`.

Миграция. Существующие пользователи с email остаются `false`, кроме случая «при OAuth Яндекс email уже сохранён» — при следующем логине/обмене можно выставить `true` (только для yandex).

## UI

- Страница входа: форма сброса **уже есть** — без больших правок, только чтобы письма реально приходили.
- Профиль / редактирование профиля: блок «Почта» — статус + «Отправить код» + поле кода + «Подтвердить».
- Мягкий баннер (как recovery), если есть email и `email_verified=false`. Можно закрыть (localStorage snooze 7 дней).

## Почта (SMTP)

Env (обязательно для прода):

```
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=...
EMAIL_PORT=587
EMAIL_HOST_USER=...
EMAIL_HOST_PASSWORD=...
EMAIL_USE_TLS=true
DEFAULT_FROM_EMAIL=Academy <noreply@ваш-домен>
```

Письмо: простой текст (тема + код + «действует 15 минут»).  
Ошибки отправки логируем; пользователю — общий текст без деталей SMTP.

**Нужно от вас после APPROVED:** данные SMTP (Яндекс Почта / Selectel / другой сервис), чтобы прописать на сервере.
