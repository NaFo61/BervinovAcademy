# ИИ-помощник: базовый шаблон + свой текст на задачу

**Статус:** APPROVED

## Цель

Владелец/ментор задаёт **один базовый текст** для ИИ (как говорить, что подставлять).  
Для отдельной задачки можно **переопределить** этот текст, если она особенная.

Студент по-прежнему просто спрашивает в «Помощь → ИИ».

---

## Как это выглядит для вас

### 1. Базовый шаблон (один на всю школу)

В админке: раздел вроде **«ИИ-помощник → Базовый промпт»**.

Пример текста (можете править как угодно):

```text
Ты помощник ученика. Отвечай по-русски коротко и чётко.
Не выдавай полное решение сразу — сначала наводящие подсказки.

Условие:
{{condition}}

Тесты:
{{tests}}

Вопрос ученика подставится отдельно.
```

Плейсхолдеры (подставляются сами):

| Плейсхолдер | Что подставится |
|-------------|-----------------|
| `{{condition}}` | условие / описание задачи |
| `{{tests}}` | публичные тесты (ввод→ожидаемый вывод), если есть |
| `{{title}}` | название задачи |
| `{{course}}` | название курса |
| `{{code}}` | код ученика, если фронт его передаст |

### 2. Свой текст на задачу

У **CodingChallenge** (задача с кодом) поле **«Промпт ИИ (свой)»**.

- Пусто → берётся **базовый** шаблон.  
- Заполнено → для этой задачи используется **только свой** текст (те же плейсхолдеры).

Редактирование:

- в Django admin у задачи;
- в панели ментора (редактор контента) — то же поле.

### 3. Другие типы уроков (теория, короткий ответ…)

Пока без своего поля: всегда базовый шаблон + то, что уже уходит с фронта (`lesson_statement` и т.п.).  
Свой текст на не-coding уроки — вне скоупа этой версии.

## User stories

1. Как владелец, я один раз пишу базовый стиль ответов ИИ.  
2. Как ментор, для одной «странной» задачи пишу свой промпт.  
3. Как студент, спрашиваю в чате — ИИ видит условие/тесты из шаблона + мой вопрос.

## Acceptance criteria

- [x] В админке есть singleton «базовый промпт» с дефолтным текстом при первом запуске (миграция/seed).
- [x] Пустой override на задаче → базовый шаблон.
- [x] Заполненный override → только он.
- [x] `{{condition}}` / `{{tests}}` / `{{title}}` / `{{course}}` подставляются; неизвестные `{{...}}` → пустая строка.
- [x] Без ключа Gemini по-прежнему mock; с ключом — system prompt из шаблона.
- [x] Вопрос ученика идёт отдельным user-сообщением.
- [x] Тесты pytest: render плейсхолдеров; override > base; mock/llm без реального Google.

## API (для разработки)

Без новых публичных student-endpoint’ов для шаблона: сборка промпта **на бэкенде** при `POST /api/mentoring/assistant/chat/`.

Тело запроса (расширение `context`):

```json
{
  "message": "почему тест падает?",
  "history": [],
  "context": {
    "course_title": "...",
    "lesson_kind": "coding",
    "lesson_title": "...",
    "lesson_statement": "...",
    "lesson_public_id": "<uuid задачи>",
    "user_code": "optional",
    "tests_blurb": "optional — или бэкенд сам подтянет по public_id"
  }
}
```

**Решение:** если передан `lesson_public_id` и kind=coding — бэкенд сам читает задачу, override и публичные тесты (надёжнее, чем доверять только фронту).  
Фронт всё равно может слать `lesson_statement` / `user_code` как дополнение.

Mentor/editor API: поле `assistant_prompt` в serializer редактора coding challenge (create/update/retrieve).

Admin: `AssistantSettings` (singleton) + поле на `CodingChallenge`.

## DB / migrations

1. Модель `mentoring.AssistantSettings` (или `content`):  
   - `base_prompt` TextField  
   - singleton (pk=1 / `get_solo`)

2. `CodingChallenge.assistant_prompt` TextField blank=True  
   help_text: «Пусто = базовый шаблон школы»

Дефолт `base_prompt` — осмысленный русский текст с `{{condition}}` и `{{tests}}`.

## Test plan
